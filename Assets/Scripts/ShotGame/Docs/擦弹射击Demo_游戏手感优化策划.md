# 擦弹射击 Demo：游戏手感优化策划

> 文档状态：策划基线 V1。
>
> 本文只定义手感目标、反馈规则、参数基线和验收方式，不规定具体代码结构。工程实现以《07_游戏手感优化与反馈表现计划》为准。

## 1. 策划目标

当前 Demo 已经形成完整玩法循环：

```text
射击产生后坐位移
  → 玩家主动进入危险路线
  → 提交擦弹窗口
  → 擦弹获得充能与子弹时间
  → 下一次射击消费强化
  → 通过五个波次完成一局
```

手感优化不改变这条循环，而是让其中每个关键动作都具备清楚、及时且有层次的反馈，使玩家无需阅读数值也能理解：

- 是否成功开火。
- 使用的是哪一类武器。
- 子弹是否命中以及命中什么。
- 是否完成普通擦弹或完美擦弹。
- 当前是否获得强化。
- 玩家受伤、敌人死亡和波次完成的重要程度。

最终目标是让一次简单输入产生多层但一致的回应，同时保持弹幕信息清晰，不让震动、闪光和粒子遮蔽判断。

## 2. 当前体验判断

### 2.1 已经具备的手感基础

- 散弹枪与冲锋枪具有不同射速、弹丸数量和后坐冲量。
- 后坐不只是动画，而是玩家的核心移动方式。
- 擦弹具有 Startup、Perfect、Active、Cooldown 阶段。
- 普通动势和完美动势会触发不同强度的子弹时间。
- Charge 会强化下一包弹丸的伤害、尺寸与穿透。
- 玩家、普通敌人、追击敌人和精英敌人已经有颜色与体型差异。
- 游戏具有正式波次、胜负与结算流程。

### 2.2 当前主要缺口

- 开火只有弹丸和位移，没有枪口、声音和镜头层反馈。
- 命中位置、方向和墙体命中结果没有传给表现层。
- 敌人受伤缺少闪白、形变、火花和击退确认。
- 敌人死亡后立即消失，缺少释放感和战斗痕迹。
- 当前 HUD 以调试文本为主，生命、伤害、擦弹窗口和 Charge 变化缺少图形化反馈。
- 玩家无法快速判断自己和敌人的剩余生命，连续受伤时也看不出单次损失量。
- 命中虽有逻辑结果，但缺少伤害数字这一层直接、量化的命中确认。
- 玩家受伤主要依赖生命文字变化，危险反馈不足。
- 擦弹只有文字、颜色和慢动作，尚未成为画面高潮。
- 相机固定且没有后踢、震动或瞄准偏移。
- 墙体和战场不会回应射偏的子弹。
- 设置页没有减少震动、减少闪光或音量选项。

## 3. 手感核心原则

### 3.1 优先强化主要互动

射击、后坐移动和主动擦弹是本游戏最主要的三种互动。开发成本应优先投入这些动作，不先制作与核心循环无关的复杂演出。

### 3.2 一次输入产生层叠反馈

一次有效射击至少应同时产生：

```text
弹丸
+ 枪口闪光
+ 开火声音
+ 角色/武器形变
+ 后坐位移
+ 镜头轻微后踢
```

单项效果保持短小，力量来自多项反馈在同一时刻叠加。

### 3.3 反馈首先解释事件

- 玩家弹、敌弹使用稳定且不同的颜色。
- 命中敌人、命中墙体和擦弹使用不同声音与粒子。
- 普通擦弹和完美擦弹必须可以只凭画面或声音区分。
- 玩家受伤反馈必须明显强于敌人受伤。
- 精英敌人的生成、攻击和死亡必须明显高于普通敌人。

### 3.4 强弱必须有层级

反馈强度从低到高排列为：

```text
墙体命中
  < 冲锋枪普通命中
  < 散弹枪命中
  < 普通敌人死亡
  < 普通动势擦弹
  < 玩家受伤
  < 完美动势擦弹
  < 精英死亡 / 最终胜利
```

如果所有动作都使用最大震动、最大闪光和最长停顿，玩家将无法感知真正重要的时刻。

### 3.5 表现不能破坏操作可靠性

- 镜头效果不能改变逻辑边界。
- 视觉形变不能改变 Collider 大小。
- Hit Stop 不能吞掉输入。
- 粒子不能遮住敌弹。
- 慢动作、暂停和结算不能互相覆盖时间倍率。
- 所有效果在重新开始后必须完整清理。

## 4. 视觉语言

| 对象或事件 | 主色倾向 | 形状与运动 | 目的 |
| --- | --- | --- | --- |
| 玩家 | 蓝 / 青 | 清晰轮廓、后坐拉伸 | 始终能定位玩家 |
| 玩家普通弹 | 黄 / 青 | 短尾迹、方向拉伸 | 表达速度和射击方向 |
| 玩家强化弹 | 金 / 白 / 高亮青 | 更宽尾迹、外圈光晕 | 不看 HUD 也能识别强化 |
| 敌人普通弹 | 红 / 橙 | 较大轮廓、稳定亮度 | 弹幕优先可读 |
| 高危险敌弹 | 紫红 / 白芯 | 呼吸脉冲、明显前景层 | 提示高伤或精英攻击 |
| 普通命中 | 白黄火花 | 沿命中法线喷射 | 确认命中位置 |
| 擦弹 | 青白弧线 | 围绕玩家切向划过 | 表达“擦过而非击中” |
| 玩家受伤 | 红色暗角 | 向内收缩 | 明确危险和损失 |

闪白只作为短暂冲击帧使用，不长时间覆盖对象本色。

## 5. 射击反馈

### 5.1 散弹枪

目标感受：沉重、爆发、会把玩家明显推离原位。

- 枪口闪光持续约 0.06 秒，尺寸明显大于角色。
- 五颗弹丸共用一次开火反馈，不按弹丸数量重复播放。
- 开火时视觉主体沿射击方向压缩，随后回弹。
- 镜头向射击反方向后踢 0.10～0.14 世界单位。
- 叠加一次中等、短促的屏幕震动。
- 音效突出低频和瞬间冲击。
- 命中多个目标时 Hit Stop 只按一包射击合并或限频。

### 5.2 冲锋枪

目标感受：轻、快、连续，可以通过小冲量持续修正路线。

- 枪口闪光持续约 0.035 秒，面积小于散弹枪。
- 每发只有极轻镜头后踢和形变。
- 连射声音允许小幅音高随机，避免机械重复。
- 普通命中不强制逐发 Hit Stop，只保留闪白、火花和声音。
- 连续命中可累计非常有限的镜头震动，上限低于散弹单次开火。

### 5.3 敌人武器

- 开火前使用收缩、变亮或蓄力圈进行预告。
- 出生后的 `InitialAttackDelay` 同时作为第一次攻击预警时间。
- 开火时提供枪口闪光和声音，但不使用玩家开火等级的镜头后踢。
- 精英散射的蓄力、释放和弹丸颜色必须区别于普通敌弹。

## 6. 命中与受伤反馈

### 6.1 敌人普通受击

- 受击瞬间闪白 0.04～0.06 秒。
- 命中点生成 6～10 个小型火花。
- 视觉节点沿弹丸方向短暂压缩或倾斜，然后回弹。
- 根据武器冲击力产生轻微位移击退。
- 播放普通命中音效。
- 命中点附近弹出伤害数字；数字强度与实际伤害一致，不显示理论伤害。
- 敌人头顶血条立即响应，并用延迟扣减条保留本次损失量。
- 不改变物理根节点的缩放。

### 6.2 墙体命中

- 命中点沿法线生成少量火花或尘雾。
- 散弹枪命墙的反馈大于冲锋枪。
- 墙体只进行局部亮度或非常轻微的视觉弹动。
- 可留下短时弹孔，但不能影响碰撞。
- 射偏仍然得到世界回应，但反馈强度低于命中敌人。

### 6.3 玩家受伤

- 玩家先闪红再快速恢复。
- 播放独立受伤音效。
- 使用中等屏幕震动和短时红色暗角。
- HUD 生命条前景快速扣减，延迟扣减条稍后追上，生命数字放大并回弹。
- Charge 降级时播放破碎声和碎片反馈。
- 玩家受伤反馈不能被普通命中音效覆盖。

### 6.4 Hit Stop 基线

| 事件 | 建议时长 | 说明 |
| --- | ---: | --- |
| 冲锋枪普通命中 | 0～0.008 秒 | 默认可关闭或限频 |
| 散弹枪有效命中 | 0.015～0.025 秒 | 同一 ShotPackage 合并 |
| 普通敌人死亡 | 0.035～0.05 秒 | 强于普通命中 |
| 玩家受伤 | 0.025～0.04 秒 | 之后立即恢复控制 |
| 精英敌人死亡 | 0.06～0.08 秒 | 本阶段最强停顿之一 |

Hit Stop 使用真实时间计时。暂停期间不推进，不能通过线程阻塞或 `Sleep` 实现。

## 7. 死亡反馈与战斗痕迹

### 7.1 普通敌人死亡

```text
致死命中
  → 高亮冲击帧
  → 短 Hit Stop
  → 碎片向外喷射
  → 死亡声音
  → 留下 2～4 秒淡色残影
  → 渐隐并回收
```

尸体表现是视觉副本，不继续拥有 Collider、AI 或 Gameplay Entity。

### 7.2 精英敌人死亡

- 使用更大的粒子爆发和环形冲击波。
- 使用更强但有上限的镜头震动。
- 播放独立死亡声音。
- Hit Stop 为 0.06～0.08 秒。
- 波次完成提示延迟约 0.25 秒出现，让死亡反馈有时间完成。

### 7.3 痕迹数量上限

| 表现 | 同屏或场景上限 |
| --- | ---: |
| 弹孔 | 40 |
| 弹壳 | 30 |
| 尸体残影 | 12 |
| 持续烟雾 | 16 |
| 一次性冲击特效 | 32 |

到达上限后优先回收最早生成的对象，不无限堆积。

## 8. 主动擦弹反馈

擦弹是本游戏的主卖点，其反馈等级必须高于普通射击和普通击杀。

### 8.1 擦弹窗口

| 阶段 | 表现 |
| --- | --- |
| Startup | 玩家外圈出现快速收缩光环，颜色开始变亮 |
| Perfect | 光环产生一次清晰脉冲，音效进入可成功状态 |
| Active | 保留较弱轮廓，避免持续高亮遮挡敌弹 |
| Cooldown | 光环快速淡出并转为低饱和色 |
| Idle | 清除临时表现，恢复玩家默认颜色 |

HUD 中的擦弹指示条与角色外圈表达同一阶段：指示条负责精确读取时机，角色外圈负责战斗中余光识别。两者必须同步，不能出现颜色已经进入 Perfect、指示条仍停留在 Startup 的情况。

### 8.2 普通动势擦弹

- 子弹与玩家之间生成切向火花或短弧线。
- 播放清脆确认音。
- 玩家轮廓短暂放大。
- Charge HUD 回弹一次。
- 擦弹指示条在判定点产生一次命中刻度和短促脉冲。
- Combo 数字从事件位置朝 HUD 方向移动。
- 保持当前普通动势子弹时间强度。

### 8.3 完美动势擦弹

- 使用更亮的青白环形冲击波。
- 高音确认与低频冲击叠加。
- 轻微镜头震动。
- 允许非常短的全屏亮度脉冲，但不能纯白遮屏。
- 子弹时间快速进入、平滑退出。
- Charge 等级提升时改变颜色、尺寸和提示音高。
- 擦弹指示条的 Perfect 区域瞬间高亮，并显示比普通擦弹更明确的“完美”标签。

### 8.4 防守类擦弹

防守和完美防守仍需确认反馈，但不能使用 Charge 获得表现：

- Defensive：小型蓝色火花，无 Combo 飞字。
- PerfectDefensive：更清晰的格挡环和声音，但不显示强化获得。

## 9. 镜头方案

当前游戏是固定单房间竞技场，不采用持续追随玩家的大幅移动相机。

本阶段镜头只实现：

- 朝瞄准方向偏移最多 0.25～0.40 世界单位。
- 开火时反向后踢。
- 命中、受伤、擦弹和死亡事件震动。
- 使用缓出或弹性曲线回到逻辑中心。

镜头结构应区分逻辑位置和表现偏移：

```text
CameraAnchor        稳定位置与边界参考
└── GameplayCamera  后踢、震动和微小瞄准偏移
```

震动采用可累计但有上限的强度值。连续冲锋枪命中不能无限叠加震动。

## 10. 敌人、波次与场景反馈

### 10.1 敌人生成

- 生成点先出现 0.15～0.30 秒预告。
- 敌人从 0.6 倍缩放回弹到 1 倍。
- 同批敌人加入 0～0.12 秒表现随机延迟。
- 随机延迟只影响表现，不改变已经确定的 WavePlan 逻辑顺序。

### 10.2 敌人性格

- 基础敌人：稳定、反馈简单。
- 追击敌人：移动时沿速度方向轻微拉伸。
- 精英敌人：持续呼吸缩放，攻击前明显收缩蓄力。

### 10.3 波次

- 波次名称以短 Tween 进入，停留后淡出。
- 关键目标波使用独立颜色与声音。
- 最后一名敌人死亡后先完成死亡反馈，再显示波次完成。
- 最终胜利时清理敌弹，并将敌弹转为无伤害的消散粒子。
- 失败时保留最后战场画面，短暂慢动作后打开结算页。

## 11. UI 信息与手感反馈

UI 不是独立于手感之外的信息面板，而是“操作结果被玩家看懂”的最后一层。它需要同时满足：战斗中可以用余光读取、变化有动势、信息不过量。

### 11.1 HUD 总体布局

固定 HUD 建议分为三个稳定区域：

```text
左上：玩家生命、当前武器与弹药
上中：波次、目标与短时阶段标题
下中：擦弹指示条、Charge 等级与 Combo
```

- 核心状态使用图形条为主、数字为辅，不再依赖整行调试文本。
- HUD 不跟随镜头震动，避免关键读数抖动。
- 危险区域附近不放常驻 UI，保证敌弹轮廓清晰。
- 1920×1080 为设计基准，并通过 Canvas Scaler 适配不同宽高比与安全区。

### 11.2 玩家生命条

玩家生命条包含底框、即时生命条、延迟扣减条和当前/最大生命数字：

```text
受到伤害
  → 即时生命条在 0.06～0.10 秒内缩短
  → 损失段保留 0.18～0.25 秒
  → 延迟扣减条在 0.25～0.40 秒内追上
  → 整体轻微缩放回弹，生命数字短暂变亮
```

- 延迟扣减条只表现生命损失，不参与真实生命计算。
- 生命低于 30% 时进入低血量状态：颜色、边缘脉冲和提示音加强，但不高频闪屏。
- 连续受伤时即时条以最新生命为准，延迟条从当前显示位置继续追赶，不重置到满血。
- 治疗功能若后续加入，使用独立的绿色增长段；本阶段不提前实现治疗逻辑。

### 11.3 敌人头顶血条

- 普通敌人满血时默认隐藏，首次受伤后淡入；若 2 秒内未受伤可降低透明度。
- 精英和关键目标的血条常驻，并有更明显的外框或名称。
- 血条跟随 Entity 的 `HealthBarAnchor`，始终保持屏幕朝向和固定像素尺寸，不随 Entity 挤压变形。
- 即时条和延迟扣减条采用与玩家生命条相同的变化语言，但动画时间可更短。
- 敌人死亡时血条立即停止更新，随死亡反馈快速淡出，不保留可交互对象。
- 同屏敌人过多时仅显示受伤、精英或离玩家较近的血条，避免形成 UI 墙。

### 11.4 伤害数字

- 伤害数字从命中点略向上弹出，先放大、再回落、最后淡出，总时长约 0.45～0.70 秒。
- 普通伤害使用稳定主色；致死伤害尺寸更大；强化伤害增加描边或颜色层级。
- 数值来自 `DamageResult.AppliedDamage`，使用整数化显示规则，零伤害不生成普通伤害数字。
- 散弹同一轮射击命中同一目标时优先合并为一个总伤害数字，避免五个数字完全重叠。
- 冲锋枪伤害数字允许连续出现，但同一目标短时间内进行位置错开与数量封顶。
- 飘字是视觉对象，不带 Collider，不参与 Entity 查找，并通过对象池复用。
- 伤害数字默认只显示玩家造成的伤害；玩家受到的伤害由生命条、红色暗角和受伤反馈表达，避免视线中心拥挤。

### 11.5 擦弹指示条

擦弹指示条是主动擦弹的精确时机仪表，不能只显示当前枚举文字。建议结构：

```text
冷却遮罩
Startup 区间
Perfect 判定区
Active 区间
移动指针
Charge 等级与持续时间环/条
Combo 数字
```

- 按下擦弹后，指针按真实判定时间依次经过 Startup、Perfect、Active 和 Cooldown。
- Perfect 区必须在颜色之外再使用刻度、形状或亮度区别，保证色觉可访问性。
- 成功擦弹时在实际命中时刻打出刻度脉冲；完美擦弹使用更强回弹和独立文字。
- Cooldown 使用低饱和遮罩，并明确显示下一次可用时机。
- Charge 获得时填充条快速增加后轻微回弹；降级时损失段碎裂或向外消散。
- Combo 只在大于零时突出显示，中断后快速缩小并淡出，不长期占据高视觉权重。
- 擦弹指示条、角色外圈和实际 `GrazePhase` 共用同一数据源，不在 UI 内重复计时。

### 11.6 UI 动画层级与限制

| 事件 | UI 反馈强度 |
| --- | --- |
| 普通伤害 | 小幅上飘和淡出 |
| 敌人受击 | 头顶血条短促响应 |
| 玩家受伤 | 生命条损失段、数字回弹和低血提示 |
| 普通擦弹 | 指示条刻度脉冲、Charge 增长 |
| 完美擦弹 | 指示条强回弹、完美标签、Charge 升级强调 |
| 玩家死亡 | HUD 降低饱和并让位于失败结算 |

- UI 动画使用 Unscaled Time，在子弹时间内仍保持可读；暂停时冻结。
- 高频事件不能让整个 HUD 不断缩放，只动画发生变化的局部元素。
- 飘字、血条和提示达到上限后优先合并或复用，不能靠无限实例化增加表现力。

## 12. 声音设计

声音优先级：

```text
玩家死亡 / 完美擦弹
  > 玩家受伤 / 精英死亡
  > 散弹枪开火 / 普通敌人死亡
  > 普通命中 / 冲锋枪开火
  > 墙体命中 / UI 细节
```

最低需要以下声音：

- 散弹枪开火。
- 冲锋枪开火。
- 普通命中。
- 墙体命中。
- 普通敌人死亡。
- 精英敌人死亡。
- 玩家受伤与死亡。
- 普通擦弹与完美擦弹。
- Charge 获得、升级和丢失。
- 波次开始、胜利和失败。

连续事件允许小幅音高随机，但音量随机范围要小。玩家关键反馈不得因同时播放大量敌人声音而听不清。

## 13. 可访问性与舒适度

设置页至少增加：

- 屏幕震动：关闭、低、标准。
- 减少闪光：开关。
- Hit Stop：开关。
- 音效音量。
- 伤害数字：开关。
- 敌人血条：受伤时显示、始终显示、关闭。

约束：

- 关闭震动不能影响后坐移动等 Gameplay 规则。
- 减少闪光后以描边、颜色或形变替代纯亮度脉冲。
- 所有重要信息不能只通过红绿差异表达。
- 不使用长时间全屏白闪。

## 14. 性能原则

- 枪口、命中、死亡、弹孔和飘字全部复用对象池。
- 敌人血条只在 Entity 存活期间绑定，Entity 回收时同步释放或回池。
- 同屏伤害数字建议上限 24，普通敌人血条建议上限 12；达到上限先合并同目标数据。
- 高频冲锋枪事件共享限频器，避免每发创建多层对象。
- 不为 Demo 自制复杂 Tween 引擎，使用少量可复用曲线函数。
- 不制作运行时复杂网格碎裂。
- 不让每个表现对象拥有独立业务 `Update`。
- 同时开启全部效果后仍需在目标设备维持稳定帧率。

## 15. 实施优先级

### P0：形成核心反馈闭环

1. 开火闪光、声音、形变和镜头后踢。
2. 命中位置事件、敌人闪白、火花和命中声音。
3. 普通/精英死亡反馈。
4. 玩家受伤和死亡反馈。
5. 普通/完美擦弹完整表现。
6. Hit Stop 与现有子弹时间统一仲裁。
7. 玩家生命条、敌人头顶血条、伤害数字和擦弹指示条。

### P1：提升可读性与世界回应

1. 子弹尾迹和强化弹分级表现。
2. 敌人生成、移动形变和攻击预警。
3. 墙体命中、弹孔、弹壳和尸体残影。
4. 波次开始、结束、胜利和失败过渡。
5. 震动、闪光、Hit Stop 和音量设置。

### P2：最终打磨

1. 音高和粒子随机偏差。
2. 细化不同敌人和不同武器的反馈性格。
3. 依据外部试玩调整数值。
4. 优化对象池上限和低配表现。

## 16. 暂不实施

- 通用 Tween 插件或复杂时间轴系统。
- 运行时网格切割和物理碎尸。
- 大幅跟随玩家的动态相机。
- 随机爆炸直接改变伤害或关卡平衡。
- 为每个特效单独建立 MonoBehaviour 状态机。
- 在手感基线稳定前重新设计武器、波次和 AI。

## 17. 试玩与验收方式

每项效果必须支持单独关闭，并进行 A/B 对照：

1. 关闭全部表现，只保留 Gameplay。
2. 只开启声音。
3. 开启声音与命中反馈。
4. 开启镜头和 Hit Stop。
5. 开启全部效果。

邀请不了解代码的新玩家试玩，观察而不是提前解释：

- 能否区分两把玩家武器的重量。
- 能否仅凭反馈判断子弹命中敌人还是墙体。
- 能否看懂擦弹成功、完美和 Charge 升级。
- 能否在弹幕中持续定位玩家和危险敌弹。
- 是否感觉震动、闪光或停顿过量。
- 失败后是否理解自己为何受到伤害。
- 能否在不读调试文字的情况下判断生命损失、敌人残血和擦弹时机。
- 伤害数字是否强化命中感，而不是遮挡敌人和弹幕。

## 18. 策划验收标准

- 两把玩家武器即使使用相同占位美术，也能凭声音、后踢和形变区分。
- 每次有效命中在一帧内开始产生确认反馈。
- 普通命中、死亡、玩家受伤和完美擦弹具有明确强度层级。
- 不看 HUD 也能识别强化弹与普通弹。
- 擦弹反馈不会遮住下一颗敌弹。
- 镜头震动不会导致角色边界、瞄准或碰撞异常。
- 高频连射不会导致震动持续失控或游戏频繁停顿。
- 关闭震动、闪光或 Hit Stop 后玩法结果不变。
- 返回菜单和重新开始后不残留声音、特效、镜头偏移或时间倍率。
- 全部效果启用时无明显持续 GC 峰值和帧率下降。
- 玩家、普通敌人和精英的生命状态能在一眼内区分。
- 生命即时条与延迟扣减条正确表现每次损失，连续受伤不会回弹到错误数值。
- 擦弹指示条与 Gameplay 判定阶段同步，慢动作和低帧率下不产生视觉误导。
- 散弹和冲锋枪高频命中时，伤害数字仍清晰且不遮蔽危险弹幕。
