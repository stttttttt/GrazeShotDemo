# 第一部分：启动、主菜单与 Gameplay 加载流程

> 状态：代码框架已完成。本文用于快速定位入口、状态归属和调用链。

## 1. 本层目标

第一部分只负责应用生命周期，不实现具体战斗规则：

- `GameEntry` 是唯一总入口和 Gameplay Tick 驱动源。
- `UIService` 管理主菜单、加载、局内 HUD、设置和暂停页面。
- `SceneService` 加载和卸载 Gameplay 场景。
- `GameAppFlow` 只管理状态注册、合法流转和排队跳转。
- `EntryState`、`MainMenuState`、`GameplayState`、`PauseState`、`CloseGameState` 分别实现具体流程。
- 小游戏流程不设置 Loading 状态或 Loading 页面；加载工作直接由 `GameplayState.EnterAsync` 完成。
- `GameplaySession` 是一局游戏的生命周期根，下一部分再向其中加入 `GameplayRun` 和 `GameplayWorld`。

## 3. 架构关系

```mermaid
flowchart TD
    GE[GameEntry<br/>唯一总入口与 Tick 驱动]
    AF[GameAppFlow<br/>状态注册与流转]
    STATES[AppFlow States<br/>各状态具体流程]
    CTX[AppFlowContext<br/>共享依赖与 Session]
    TS[GameTimeService<br/>暂停与时间倍率]
    IS[InputModeService<br/>UI / Gameplay Action Map]
    SS[SceneService<br/>纯 C# 单例]
    UI[UIService<br/>Mono 单例]
    RS[CatalogResourceService<br/>资源加载]
    SESSION[GameplaySession<br/>一局生命周期根]

    GE -->|创建并驱动| AF
    GE -->|每帧 Tick| TS
    GE -->|初始化| IS
    GE -->|初始化| SS
    GE -->|配置并初始化| UI
    GE -->|创建| RS

    AF -->|进入 / 退出| STATES
    STATES -->|使用| CTX
    CTX -->|切换输入模式| IS
    CTX -->|加载或卸载 Gameplay 场景| SS
    CTX -->|打开或关闭页面| UI
    UI -->|实例化 UI Prefab| RS
    STATES -->|GameplayState.Enter 创建| SESSION
    CTX -->|持有当前| SESSION
    GE -->|经由 GameAppFlow 驱动| SESSION
```

核心边界：

- `GameEntry` 负责组装，不实现业务规则。
- `GameAppFlow` 负责状态流转，不包含页面、场景和 Session 加载细节。
- 每个 State 负责自身的 `EnterAsync` 和 `ExitAsync`。
- `AppFlowContext` 提供状态共享依赖，并持有当前 Session。
- `SceneService` 只负责场景，不拥有 Session。
- `UIService` 只负责页面显示，不决定当前流程。
- `GameplaySession` 只在 Gameplay 场景加载成功后创建。

约束：

- Gameplay Runtime 不自行创建 Mono 驱动器。
- 需要初始化、Update 或 FixedUpdate 的普通对象统一由 `GameEntry` 调度。
- UI 是 Unity 显示边界，可以继承 Mono。
- `SceneService` 不继承 Mono，异步操作通过 Unity `AsyncOperation` 和 `Task` 完成。

## 5. 启动流程

```mermaid
sequenceDiagram
    participant Unity
    participant Entry as GameEntry
    participant Services as AppServiceGroup
    participant Flow as GameAppFlow
    participant Input as InputModeService
    participant UI as UIService

    Unity->>Entry: Awake
    Entry->>Entry: 校验 FoundationConfig / Catalog / AppConfig
    Unity->>Entry: Start
    Entry->>Entry: ComposeApplication
    Entry->>Services: InitializeAsync
    Services->>Input: InitializeAsync
    Services->>UI: InitializeAsync
    Services-->>Entry: 初始化完成
    Entry->>Flow: StartAsync
    Flow->>Flow: 进入 EntryState
    Flow->>Input: SetMode(Disabled)
    Flow->>Flow: EntryState 排队请求 MainMenu
    Flow->>Flow: 进入 MainMenuState
    Flow->>Input: SetMode(UI)
    Flow->>UI: OpenAsync(MainMenu)
    UI-->>Flow: 主菜单已打开
```

初始化顺序由 `AppServiceGroup` 明确控制。某项服务初始化失败时，已经初始化的服务会按反向顺序释放。

## 6. 点击开始游戏

```mermaid
sequenceDiagram
    actor Player
    participant Menu as MainMenuScreen
    participant Flow as GameAppFlow
    participant UI as UIService
    participant Input as InputModeService
    participant Scene as SceneService
    participant Session as GameplaySession

    Player->>Menu: 点击开始
    Menu->>Flow: ChangeStateAsync(Gameplay)
    Flow->>Flow: MainMenuState.Exit
    Flow->>Flow: GameplayState.Enter
    Flow->>Input: SetMode(Disabled)
    Flow->>Scene: LoadAdditiveAsync(Gameplay)
    Scene-->>Flow: Gameplay 场景加载并激活
    Flow->>Session: new GameplaySession
    Flow->>Session: InitializeAsync
    Session-->>Flow: 初始化完成
    Flow->>UI: OpenAsync(GameplayHud, Session)
    Flow->>Input: SetMode(Gameplay)
```

`GameplayState.EnterAsync` 直接完成首次进入流程：

```text
加载 Gameplay 场景
  → 创建 GameplaySession
  → 初始化 GameplaySession
```

只有以上步骤全部成功，`GameplayState.EnterAsync` 才算完成。由 Pause 返回 Gameplay 时，已有 Session 会被直接恢复，不重复加载场景。

## 7. 加载失败回滚

```mermaid
flowchart TD
    START[GameplayState.Enter]
    LOAD[加载 Gameplay 场景]
    CREATE[创建并初始化 GameplaySession]
    OK{全部成功?}
    DISPOSE[Dispose Session]
    UNLOAD[卸载已加载 Gameplay 场景]
    RESTORE[GameFlowMachine 恢复原状态]
    MENU[MainMenuState 重新 Enter]
    GAME[GameplayState Enter 完成]

    START --> LOAD --> CREATE --> OK
    OK -->|是| GAME
    OK -->|否| DISPOSE --> UNLOAD --> RESTORE --> MENU
```

回滚后不会留下半初始化 Session、已加载场景或错误的输入模式。

## 8. 每帧驱动

```mermaid
flowchart TD
    UPDATE[GameEntry.Update]
    TIME[GameTimeService.Tick]
    TIMER[TimerScheduler.Tick]
    FLOW[GameAppFlow.Tick]
    CHECK{当前稳定处于 Gameplay?}
    SESSION[GameplaySession.Tick]

    UPDATE --> TIME --> TIMER --> FLOW --> CHECK
    CHECK -->|是| SESSION
    CHECK -->|否| END[结束本帧]

    FIXED[GameEntry.FixedUpdate]
    FCHECK{当前稳定处于 Gameplay?}
    FIXED --> FCHECK
    FCHECK -->|是| FSESSION[GameplaySession.FixedTick]
```

`GameplaySession` 只在当前稳定状态为 `Gameplay` 时推进；`Pause` 和状态切换过程中不会推进。

## 9. 暂停与恢复

```mermaid
sequenceDiagram
    participant Request as Pause Request
    participant Flow as GameAppFlow
    participant Time as GameTimeService
    participant Input as InputModeService
    participant UI as UIService

    Request->>Flow: ChangeStateAsync(Pause)
    Flow->>Flow: GameplayState.Exit → PauseState.Enter
    Flow->>Time: SetPaused(true)
    Flow->>Input: SetMode(UI)
    Flow->>UI: OpenAsync(Pause)

    Note over Flow,UI: 若暂停页加载失败，恢复 Gameplay 输入和时间

    UI->>Flow: ChangeStateAsync(Gameplay)
    Flow->>Flow: PauseState.Exit → GameplayState.Enter
    Flow->>UI: Close(Pause)
    Flow->>Input: SetMode(Gameplay)
    Flow->>Time: SetPaused(false)
```

暂停页面是 Gameplay 上方的 Popup，不创建新场景，也不销毁 Session。

## 10. 返回主菜单

```mermaid
sequenceDiagram
    participant Pause as PauseScreen
    participant Flow as GameAppFlow
    participant Input as InputModeService
    participant Time as GameTimeService
    participant Session as GameplaySession
    participant Scene as SceneService
    participant UI as UIService

    Pause->>Flow: ChangeStateAsync(MainMenu)
    Flow->>Flow: PauseState.Exit → MainMenuState.Enter
    Flow->>Input: SetMode(Disabled)
    Flow->>Time: SetPaused(false)
    Flow->>UI: Close(Pause / GameplayHud)
    Flow->>Session: Dispose
    Flow->>Scene: UnloadAsync(Gameplay)
    Flow->>Input: SetMode(UI)
    Flow->>UI: OpenAsync(MainMenu)
```

销毁顺序固定为：先停止输入，再释放局内对象，最后卸载场景。

## 11. 状态流转图

```mermaid
stateDiagram-v2
    [*] --> Entry
    Entry --> MainMenu
    Entry --> CloseGame
    MainMenu --> Gameplay: 开始游戏
    MainMenu --> CloseGame: 退出
    Gameplay --> Pause: 暂停
    Gameplay --> MainMenu: 结束或返回
    Gameplay --> CloseGame: 关闭游戏
    Pause --> Gameplay: 恢复
    Pause --> MainMenu: 返回菜单
    Pause --> CloseGame: 关闭游戏
    CloseGame --> [*]
```

`GameAppFlow` 会拒绝图中未声明的跳转。同一次状态进入过程中产生的下一状态请求会排队，在当前 `EnterAsync` 完成后统一执行，避免状态机重入。

## 12. 当前需要在 Unity 中配置的资产

代码框架已经存在，但要实际运行还需要配置：

1. 创建并加入 Build Settings 的 Gameplay 场景。
2. 在启动场景中添加 `GameEntry` 和 `UIService`。
3. 给 `GameEntry` 绑定：
   - `GameFoundationConfig`
   - `GameResourceCatalog`
   - `UIService`
4. 创建并注册以下 UI Prefab：
   - `MainMenu`
   - `GameplayHud`
   - `Pause`
   - `Settings`
5. 在 `GameResourceCatalog` 和 `UIService` 中建立 PageId 与 ResourceId 对应关系。页面与场景 ID 由使用它们的流程状态自行声明。

## 13. 后续扩展点

- `GameplaySession.InitializeAsync`：创建 `GameplayRun` 和 `GameplayWorld`。
- `GameplaySession.Tick`：按确定顺序推进 World。
- `GameplaySession.FixedTick`：推进固定步长移动和物理查询。
- `GameplayRun`：管理倒计时、波次、胜利、失败和结算。
- `GameplayWorld`：持有并推进本局 Entity。
