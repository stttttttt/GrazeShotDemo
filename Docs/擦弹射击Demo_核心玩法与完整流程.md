# 1. 游戏定义

## 1.1 一句话玩法

一款俯视角波次制动作射击游戏：**枪既是武器，也是玩家唯一的推进器**。玩家进入固定 Gameplay 战场，朝鼠标方向射击，同时被后坐力推向反方向；主动贴近弹幕并在后坐过程中完成擦弹，便能把风险兑换成慢动作与强化后的下一枪。玩家连续完成有序波次，完成最终波次目标即赢得本局。

## 1.2 设计内核

这套玩法真正卖的不是“射得准”，而是“用射击同时解决两个互相冲突的问题”：

- 子弹向前，解决敌人。
- 身体向后，解决位置。
- 敌弹从身边掠过，危险被兑换成下一轮进攻资源。

因此，每次扣动扳机都是一次三重判断：

1. 这一枪能否命中或形成压制？
2. 反冲会把我送到哪里？
3. 那条路径能否安全擦过敌方弹幕？

如果只保留命中，这会退化成普通俯视角射击；如果反冲只是视觉动画，移动内核就不存在；如果擦弹不要求主动规划反冲路径，它会退化成被动奖励。三者必须锁在同一次操作里。

## 1.3 三根玩法支柱

### 射击即移动

默认不提供 WASD 常规移动。鼠标瞄准决定枪口方向，开火产生反向冲量。武器的后坐力、射速和弹匣同时决定攻击方式与移动方式。

### 风险可以升值

玩家不是单纯远离弹幕，而是寻找“足够危险、但能控制”的路线。玩家在后坐位移中主动按右键完成擦弹，才会给下一枪充能并触发短暂子弹时间；连续完成动势擦弹会继续抬高收益。

### 武器就是角色构筑

换枪不只是换伤害数字，而是换一套移动语法。散弹枪是大跳，冲锋枪是连续微调，蓄力枪是先锁定风险、再一次爆发位移。

# 2. 玩家体验目标

## 2.1 新手的第一层乐趣

- 鼠标指向敌人，左键开枪。
- “咚”的一声，敌人受伤，自己被推开。
- 反冲经过一颗敌弹时按下右键，角色闪绿，画面瞬间变慢，下一枪明显变大。

玩家在 30 秒内不用读说明，也应明白“枪会推动我”和“反冲途中按右键擦弹有好处”。

## 2.2 熟练后的第二层乐趣

- 预判后坐终点，而不是只盯准星。
- 利用不同枪械的射击节奏修正轨迹。
- 故意切入弹幕边缘，连续擦弹积累强化等级。
- 把强化弹留给高价值目标、掩体后的敌人或 Boss 破绽。
- 用换枪、换弹和右键擦弹管理失控风险。

## 2.3 高光时刻

理想的高光不是“随机暴击”，而是一条玩家能复述的因果链：

```text
开枪后撤
  -> 切入两颗敌弹之间
  -> 右键开启绿色窗口
  -> 在反冲中完成动势擦弹
  -> 自动慢动作
  -> 继续修正瞄准并完成连续擦弹
  -> 强化弹穿墙击杀精英
  -> 反冲同时落入安全区
```

# 3. 输入方案

所有输入必须通过 Unity Input System 的 Input Action 配置，不在 Gameplay 代码中直接读取固定按键。键鼠为首发设备，但 Action 层保留重绑定、手柄和辅助瞄准扩展空间。

| Action | 默认输入 | 行为 |
|---|---|---|
| Move | WASD / 左摇杆 | 产生持续 Move Ability，移动强度由角色配置决定 |
| Aim | 鼠标位置 | 决定枪口与射击方向 |
| Fire | 鼠标左键 | 点射、按住连发、按住蓄力，由武器配置决定 |
| Graze | 鼠标右键 | 按下开启短暂擦弹窗口；成功时才触发对应奖励 |
| Reload | R | 主动换弹；是否允许打断由武器配置决定 |
| SwitchWeaponNext | 鼠标滚轮 | 循环切换武器 |
| SwitchWeapon | 数字键 1-3 | 直接选择武器槽 |
| QuickSwap | Q | 在当前与上一把武器之间切换 |
| Pause | Esc | 暂停并进入 UI Action Map |

当前技术基线已启用 Move Action，并以持续 Ability 实现。若要保留“后坐力为主要位移”的玩法，应通过 Archetype 的 MoveSpeed 调整移动强度，而不是建立第二套移动入口。

# 4. 核心循环

## 4.1 秒级战斗循环

```text
[观察敌人前摇与弹道]
            |
            v
[选瞄准方向和后坐落点]
            |
            v
[开火: 伤害向前 / 位移向后]
            |
            v
[沿反冲轨迹接近弹幕并按右键]
      |             |
      | 被击中      | 擦弹成功
      v             v
[受伤与失去连段] [充能 + 自动慢动作]
                         |
                         v
                 [强化下一次射击]
                         |
                         v
                 [击杀 / 破甲 / 清障]
                         |
                         +------> 回到观察
```

## 4.2 波次级循环

```text
波次开始提示
  -> 按时序和出生点分组生成敌人
  -> 歼灭全部敌人或击杀关键目标
  -> 关键目标波正常结算剩余敌人
  -> 敌人掉落与波次奖励生成在战场
  -> 玩家保持控制并拾取所需奖励
  -> 间隔结束后自动开始下一波
```

## 4.3 单局循环

```text
主菜单
  -> 选择初始武器
  -> 进入 Gameplay 战场
  -> 初始倒计时
  -> 教学 / 低压波次
  -> 普通波次与战场掉落
  -> 精英或关键目标波次
  -> 最终波次
  -> 胜利结算 / 死亡结算
  -> 重开或返回主菜单
```

第一轮目标时长建议 12 至 18 分钟；如果当前仍以面试 Demo 为目标，则裁成 5 至 8 个波次、6 至 10 分钟。随机化只改变每波预算内的普通敌人组合；显式配置的关键内容、波次顺序和目标不会被随机系统替换。

# 5. 射击与后坐移动

## 5.1 一次射击的权威流程

```text
输入触发
  -> WeaponRuntime 检查状态、弹药、冷却和蓄力
  -> 生成一个 ShotPackage
  -> 扣除弹药并进入冷却
  -> WeaponExecution 生成弹丸或命中扫描
  -> CharacterMotor 接收反向冲量
  -> GrazeRuntime 打开本次反冲窗口
  -> 发布 ShotFiredFact 给表现层
```

`ShotPackage` 是一次扳机行为的结算单位。散弹枪的一组弹丸、三连发的一整个短点射，都可以归为一个包，避免按弹丸数量重复消耗充能 Buff。

## 5.2 后坐移动模型

后坐不建议直接瞬移，也不建议完全交给无约束 Rigidbody2D。推荐由 `CharacterMotor` 统一拥有速度，并按配置执行：

- 发射瞬间添加反向冲量。
- 使用曲线控制加速、峰值和衰减。
- 限制最大速度，防止高射速武器数值爆炸。
- 与墙体发生滑动或反弹，具体行为由武器或玩家配置决定。
- 反冲期间仍可转动瞄准，但是否允许下一枪快速改向由武器决定。
- 连射武器的多次小冲量可叠加，但必须有速度上限和阻尼。

建议拆开三个概念：

| 参数 | 作用 |
|---|---|
| RecoilImpulse | 单次射击给玩家多大初速度 |
| RecoilControl | 玩家能多快通过下一枪改变当前轨迹 |
| RecoilRecovery | 不再射击后多快停下 |

这样才能做出“大后坐但容易修正”和“小后坐但容易失控”的不同武器性格。

## 5.3 换弹的意义

换弹是移动系统的强制断句。没有子弹就没有主动位移，因此弹匣容量和换弹时间也是生存参数。

- 允许提前换弹，但默认会丢弃当前弹匣的余弹与否，应由难度定位决定。
- 普通换弹可被切枪打断；重型武器可配置为阶段式换弹。
- 空仓点击可自动开始换弹，但 UI 和音效必须明确提示玩家进入了无推进状态。
- 换弹期间仍可按右键进行防守擦弹，但因为没有后坐位移，只能化解风险，不获得充能与奖励慢动作。

# 6. 主动擦弹、动势奖励与充能

## 6.1 核心规则

擦弹不再被动触发。玩家必须按下鼠标右键，主动开启一次很短的绿色擦弹窗口：

- **防守擦弹**：擦弹成功时，玩家不处于后坐位移。它可以避开或弹开这一发敌弹，但不给充能、连段和奖励慢动作。
- **动势擦弹**：擦弹成功时，玩家仍处于本次开火产生的有效反冲位移。它会给予充能、连段，并自动触发短暂子弹时间。
- **完美动势擦弹**：敌弹在绿色窗口的最精确阶段接触内层 Hurtbox。伤害被抵消，敌弹被弹开或销毁，并给予最高档奖励。
- **保护反冲**：没有开启右键擦弹窗口时，即便玩家正处于反冲，命中也只获得减伤，不算擦弹。

这里的顺序不能反：左键先创造位移路线，右键再对这条路线中的危险进行确认。右键单独使用只是防守动作，只有和后坐力重叠才进入正向收益循环。

## 6.2 检测结构

```text
+-----------------------------+
| Graze Sensor                |
|                             |
|        +-----------+        |
|        | Hurtbox   |        |
|        |  Player   |        |
|        +-----------+        |
|                             |
+-----------------------------+
```

运行规则：

1. 右键按下后，`GrazeRuntime` 开启短暂的 Active Window，角色进入绿色提示状态。
2. 敌弹进入 Graze Sensor 时，只登记为候选，不立刻奖励。
3. 敌弹命中 Hurtbox 时，若处于 Perfect Window，则拦截伤害并结算完美擦弹；否则按正常命中处理。
4. 敌弹离开 Graze Sensor 且从未命中 Hurtbox，并且离开前曾与 Active Window 重叠，才结算普通擦弹。
5. 结算瞬间检查 `CharacterMotor.IsRecoilMoving`；成立则升级为动势擦弹，否则只算防守擦弹。
6. 同一颗弹对同一玩家最多结算一次。
7. 只有具有有效敌对 Owner、尚未失效的 Projectile 才可参与擦弹。
8. 激光、持续范围和近战攻击使用独立的 GrazePolicy，不能照搬普通弹丸判定。

“右键窗口与敌弹轨迹发生重叠”以及“离开外圈后再结算”都很关键。前者保证擦弹是主动操作，后者避免最终撞上玩家的子弹也被提前当作成功擦弹。

## 6.3 右键擦弹窗口

一次反冲建议划为三个阶段：

| 阶段 | 视觉 | 规则 |
|---|---|---|
| Startup | 轮廓开始转绿 | 已提交擦弹动作，但尚未生效 |
| Perfect | 角色亮绿、轮廓收紧 | 接触 Hurtbox 可拦截敌弹并结算完美擦弹 |
| Active | 绿色逐渐消退 | 外圈近失有效，但直接命中仍会受伤 |
| Cooldown | 恢复常态 | 暂时不能再次开启擦弹窗口 |

原型起始值，不是最终平衡值：

- Startup：20ms。
- Perfect：70ms。
- Active：再持续 100ms。
- Cooldown：从按下右键起共 350ms；无论成功与否都会进入。
- 反冲期减伤：35%。
- Hurtbox 半径：玩家视觉半径的 55% 至 65%。
- Graze Sensor 半径：Hurtbox 的 1.8 至 2.2 倍。

这些时间按 UnscaledClock 记录，避免奖励子弹时间把擦弹窗口拉成长时间无敌。是否命中仍发生在 Gameplay Simulation 中。右键不消耗资源，但错误按键同样触发冷却，以阻止无脑连点。

## 6.4 充能 Buff

擦弹为下一次有效 `ShotPackage` 充能，而不是永久提高角色伤害。

建议采用三级充能：

| 等级 | 来源 | 下一枪效果 |
|---|---|---|
| 1 | 一次动势擦弹 | 伤害、尺寸与击退小幅提高 |
| 2 | 连续动势擦弹或一次完美动势擦弹 | 更高伤害，可穿透敌人 |
| 3 | 高连段完美动势擦弹 | 显著放大，可穿透标记为 LightCover 的障碍并触发专属表现 |

约束：

- 充能只在下一次成功发射后消耗；空仓点击不消耗。
- 一次散弹齐射只消耗一次，所有弹片共享经过平衡的强化模板。
- 不能穿透战场边界、Boss 场景机关和不可破坏的关键墙。
- 防守擦弹不会提高充能等级，也不能续连段。
- 玩家受伤会清除擦弹连段，但是否清空已经获得的充能可由难度决定。首版建议保留一级、损失更高等级。
- 充能有明显的角色轮廓、枪口、准星和音效提示，不能只放在 HUD 小图标上。

## 6.5 连续擦弹

连续动势擦弹的价值不是无限叠数值，而是抬高玩家的节奏和压力：

- 在 `ComboGracePeriod` 内再次完成动势擦弹，连段 +1。
- 连段提高充能获取效率、自动慢动作延长量和结算分数。
- 达到上限后只刷新持续时间，不继续指数增长伤害。
- 同一发散射攻击产生的多个子弹可分别擦弹，但设置短时间收益衰减，避免站在固定位置刷满。
- 受到真实伤害、离开战斗过久或进入整局结算时结束连段；普通波次间隔不强制中断连段。

# 7. 擦弹奖励子弹时间

## 7.1 唯一入口

玩家不能主动开启子弹时间。只有在后坐位移中完成有效擦弹，系统才自动触发一次短促慢动作；完美动势擦弹更慢、更明显。防守擦弹不会触发慢动作。

所有奖励慢动作由 `TimeDilationService` 管理，禁止其他系统直接修改 `Time.timeScale`。子弹时间从通用保命按钮变成技术动作的结果，玩家想获得思考时间，必须先正确处理一次风险。

## 7.2 时间域

| 系统 | 子弹时间内的速度 |
|---|---|
| 敌人、敌弹、环境危险 | 完整减速 |
| 玩家瞄准与输入读取 | 不减速 |
| 玩家反冲运动 | 轻度减速或保持 70% 以上速度 |
| 射击冷却与换弹 | 跟随 GameplayClock |
| UI、提示、完美窗口计时 | 使用 UnscaledClock |
| VFX 与音频 | 按 Profile 分别处理 |

如果玩家反冲和敌弹一起等比减速，子弹时间只会让等待变长，不会给玩家新的操作空间。玩家运动保留更高时间倍率，才会形成“在凝固的弹幕里调整轨迹”的感觉。

## 7.3 推荐起始参数

- 动势擦弹慢动作：0.25 倍，持续 0.18 真实秒。
- 完美动势擦弹慢动作：0.15 倍，持续 0.28 真实秒。
- 连续触发不反复重启镜头和音效，只延长当前慢动作，累计上限约 0.6 真实秒。

# 8. 生命、受伤与失败

- 玩家拥有明确但不宜过长的生命资源，建议原型从 4 至 6 次普通命中开始测试。
- 普通状态中弹：全额伤害、轻击退、短暂无敌、连段清零。
- 未按右键的反冲中弹：减伤但不触发充能，并给出与擦弹完全不同的反馈。
- 右键 Perfect Window 接弹：无伤，弹丸失效或改向；若同时处于反冲位移，则结算完美动势擦弹。
- 场景接触伤害、坠落和持续激光默认不受完美弹丸无敌保护，除非对应攻击配置明确允许。
- 死亡后停止新敌人行为，播放短结算，展示死亡来源、波次进度、最高连段和常用武器。

失败必须可解释。死亡界面至少记录最后一次伤害来源和当时状态，例如“换弹中被射手弹命中”，而不是只显示“失败”。

# 9. 武器系统

## 9.1 武器差异的四个轴

每把武器至少在以下两个轴上产生显著差异：

1. 发射语法：点射、自动、连发、蓄力、松开发射。
2. 弹道语法：直射、散射、弧线、追踪、延迟爆炸、贯穿、反弹。
3. 移动语法：单次大冲量、连续小冲量、蓄力后爆发、方向锁定、墙面反弹。
4. 充能语法：强化伤害、改变弹道、破甲、穿墙、扩大范围或生成二次攻击。

## 9.2 首批武器建议

| 武器 | 攻击身份 | 移动身份 | 擦弹强化 |
|---|---|---|---|
| 散弹枪 | 近距高爆发、扇形弹道 | 单次大跳，容易脱围也容易撞墙 | 弹片聚束并贯穿首个目标 |
| 冲锋枪 | 持续压制、散布累积 | 连续微调轨迹 | 短时间若干发变大，但总增益设上限 |
| 轨道枪 | 蓄力直线高伤 | 松开时产生强后坐 | 穿透轻型掩体与多名敌人 |
| 榴弹发射器 | 弧线范围伤害 | 中等冲量，可借爆炸二次推开 | 爆炸半径扩大并留下短暂危险区 |

首个可玩版本只做前三把。第四把用于验证框架是否真能容纳新弹道，而不是为数量服务。

## 9.3 多武器携带

- 默认 2 个武器槽；后续可通过奖励扩为 3 个。
- 每把武器独立保存弹匣、备弹、冷却和蓄力状态。
- 切枪存在短暂时间，但不应长到破坏反冲修正。
- 充能 Buff 属于玩家，不属于当前枪；切枪不会丢失，但不同枪按自己的 EmpowerProfile 解释它。
- 武器掉落以替换为主，避免背包管理压过战斗。

# 10. 敌人与 AI

## 10.1 敌人的设计职责

敌人不是只按近战、远程分类，而是按它给反冲路线制造的问题分类：

- **追猎者**：持续压缩空间，逼玩家开枪脱离。
- **射手**：用清晰前摇发射慢弹，提供可规划的擦弹材料。
- **封锁者**：制造墙、地雷或持续危险区，限制后坐落点。
- **重装者**：正面抗性高，要求强化弹、侧击或穿透。
- **牵引者**：短暂改变玩家速度或方向，考验轨迹修正。

早期组合建议只用追猎者、射手、重装者。封锁与牵引等核心手感稳定后再加入。

## 10.2 AI 架构

推荐采用“行为树负责决策，能力状态机负责执行”的组合：

```text
Perception
  -> Blackboard
  -> Behavior Tree
  -> PawnIntent / AbilityRequest
  -> Motor, Aim, Weapon, Ability State Machine
```

- 感知系统只提供视野、距离、遮挡、危险和最近一次看到玩家的位置。
- 行为树选择追击、保持距离、侧移、找射线位置、释放技能或撤退。
- 具体技能负责前摇、释放、后摇、冷却和可打断状态。
- AI 与玩家共用移动、伤害、武器和能力执行层，但使用不同 IntentSource。
- 敌人不得读取玩家未来输入；瞄准误差、反应延迟和最大转向速度都要配置化。

## 10.3 可读性规则

- 所有高伤攻击必须有前摇。
- 同一种危险颜色和声音在全游戏中保持一致。
- 同屏攻击者数量和弹丸预算由当前 Wave 的生成计划与并发上限控制。
- 出生点不能直接位于玩家当前视野盲区且立刻造成伤害。
- 精英可以组合能力，但不能删除基础敌人的反制窗口。

# 11. Gameplay 战场与波次

## 11.1 战场原则

单局只使用一个经过人工验证的 Gameplay Scene。战场负责提供边界、掩体、危险区、玩家出生点、敌人出生点分组和掉落承载点，不负责定义波次顺序或敌人数值。

战场必须保证：

- 玩家只依靠后坐移动也不会进入永久软锁区域。
- 玩家出生点、所有敌人出生点和掉落安全点位于合法边界内。
- 出生点具有稳定 Id 与逻辑 Group/Tag，可被 Wave 配置引用。
- 敌人生成有足够前摇和安全距离，不会从视野盲区立即造成伤害。

## 11.2 波次顺序与目标

`RunDefinition` 按顺序引用独立的 `WaveDefinition`。最后一个引用就是最终波次，不强制为 Boss。

首版支持两种目标：

- 歼灭：生成计划耗尽且本波要求击杀的敌人全部死亡后完成。
- 关键目标：关键目标死亡后停止后续普通生成，场上剩余普通敌人通过正常死亡流程清场并正常掉落；清场结束后完成波次。

波次之间玩家保持控制，场上掉落不会被清除。经过可配置间隔后自动开始下一波，同一时刻不得存在两个 Active Wave。

## 11.3 波次内容生成

每波采用“显式配置 + 预算权重随机”的混合方式：

- 显式生成组用于关键敌人、固定教学内容和设计者必须保证出现的组合。
- 随机池使用候选权重、Cost、数量限制和总预算补充普通敌人。
- Wave 只引用出生点逻辑 Group/Tag，不引用 Scene Transform。
- 进入 GameplayWorld 时使用 Run Seed 一次解析全部波次，形成只读 `WavePlan`。
- 相同配置、Seed 和场景绑定必须生成相同计划；掉落使用独立随机流，不能改变后续刷怪。

随机系统不得专门克制玩家当前武器，也不得删除显式关键内容。配置无法形成合法计划时必须在玩家可操作前报错，而不是运行中悄悄少刷敌人或错误判胜。

# 12. Boss 设计

Boss 复用普通敌人的生命、移动、受伤、能力和行为树框架，再增加 `BossPhaseController`：

- 按生命阈值或关键部位破坏切换阶段。
- 每阶段开放不同技能集合和行为树子树。
- 技能选择受冷却、位置、重复惩罚和场上危险预算约束。
- 转阶段时短暂停止攻击、清理或减速旧弹幕，给玩家读懂新规则的空间。

Boss 的每个核心技能都应服务于本作内核：

- 扇形慢弹：提供可选的右键动势擦弹路线。
- 瞄准重弹：鼓励精确按下右键完成完美接弹。
- 生成掩体：鼓励使用三级强化弹穿墙。
- 场地压缩：迫使玩家用大后坐武器换位。

Boss 不是“更厚的普通敌人”。建议有破绽系统：连续擦弹或强化弹命中特定阶段可削减架势，打空架势后进入短暂输出窗口。这样核心技巧在最终战仍然是最优解。

# 13. 局内奖励与构筑

奖励优先改写核心循环，不堆无感的百分比：

- 武器：替换一把枪，直接改变攻击和移动语法。
- 后坐模块：增加冲量、改变衰减、允许一次墙面反弹。
- 擦弹模块：缩小外圈但提高收益，或延长连段宽限期。
- 时机模块：缩短右键窗口换取更高收益，或降低失败冷却但削弱完美奖励。
- 充能模块：三级弹分裂、爆炸、破甲或保留部分充能。
- 生存模块：提高反冲期减伤、获得一次致命保护。

每个奖励都应有代价或身份，避免所有构筑最后都变成“更高伤害”。首版只做 8 至 12 个模块；敌人死亡和波次完成时，奖励以 Pickup 直接生成在战场。若某次奖励采用三选一，也以互斥拾取物表达，玩家拾取其中一个后回收其余候选，不打开独立奖励页面。未拾取掉落跨波保留，直到被拾取、到期或本局结束。

# 14. 反馈与信息层级

## 14.1 颜色语义

- 绿色：右键擦弹窗口与成功防护。
- 金色或高亮白：充能等级与强化弹。
- 红色：玩家实际受伤和不可擦弹危险。
- 敌方弹幕使用稳定色相，不与玩家弹和奖励混淆。

色盲模式不能只依赖换颜色，还应同步改变轮廓、闪烁频率和音效。

## 14.2 反馈优先级

```text
普通开火 < 普通命中 < 防守擦弹 < 击杀
         < 玩家受伤 < 动势擦弹 < 完美动势擦弹 < 三级强化命中 / Boss 破防
```

- 开火：枪口、音效、武器动画、玩家反冲、方向性相机 Kick。
- 防守擦弹：绿色边缘火花、短音符、弹丸偏转，不播放充能吸入和慢动作。
- 动势擦弹：充能吸入角色、自动慢动作和清晰的连段提示。
- 完美动势擦弹：绿色定格轮廓、弹丸偏转、低频冲击音，强于普通动势擦弹但不遮挡下一步输入。
- 强化射击：准星、弹丸尺寸、拖尾和命中层级全部升级。
- 受伤：红色方向提示、不同频段音效、输入保持可用，禁止长时间夺取控制。

相机基础跟随、开枪 Kick、命中 Shake 和 Boss 事件 Shake 必须分层混合，不能互相覆盖。设置中提供震动强度和闪光强度。

| FireModeSpec | Press/Hold/Burst/Charge、触发时机、连发数和间隔 |

| EmpowerProfile | 各充能等级对 ShotPackage 的修改规则 |
| EnemyArchetype | 生命、速度、感知、抗性、行为树、能力列表和价值预算 |

# 17. 必要编辑器与调试工具

## 17.1 第一优先级

### 武器试验场

- 即时切换 WeaponSpec、ProjectileSpec、RecoilProfile。
- 显示射速、实际 DPS、每秒位移、停稳时间和弹药循环。
- 生成木桩、移动目标、轻型墙体和标准敌弹。
- 支持一键重置位置和 Dry/Juicy 反馈切换。

### 擦弹调试器

- Scene Gizmo 同时显示 Hurtbox、Graze Sensor 和当前反冲阶段。
- 记录每次右键输入以及每颗候选弹的 Enter、Hit、Exit、Invalid 原因。
- 慢放或逐帧运行，显示 Startup、Perfect、Active、Cooldown 剩余毫秒和 `IsRecoilMoving`。
- 可实时调整半径、窗口、失败冷却、反冲资格、减伤和奖励慢动作参数。

### AI 行为树编辑器与运行调试

- 图形化节点编辑、子树复用、节点参数检查。
- 运行时高亮当前节点和最近失败原因。
- Blackboard 监视器可查看目标、距离、视线、冷却和选中技能。
- 节点只发出 Intent 或 AbilityRequest，不直接越层修改生命与动画。

### WaveDefinition 与战场校验工具

- 编辑显式生成组、随机池、预算、目标、时序和完成奖励。
- 校验 WaveId、关键目标、预算合法性及出生点 Group/Tag。
- 校验场景内唯一 PlayerSpawn、Spawn Point Id、DropRoot 和 ArenaBounds。
- 输入 Seed 预览完整 WavePlan、时间线、预算消耗和峰值并发。

## 17.2 第二优先级

### 波次序列与复现工具

- 可视化 RunDefinition 中的波次顺序、最终波次和间隔。
- 检查空引用、重复 WaveId、目标不可完成和连续高压波次。
- 保存失败 Seed 与解析后的 WavePlan，支持一键重现。

### 弹幕 Pattern 编辑器

- 编辑扇形、环形、序列、旋转、瞄准和延迟弹。
- 预览轨迹与时间线，不运行完整 Boss。
- 计算峰值同屏弹丸数和理论危险覆盖率。

### Boss 阶段编辑器

- 可视化生命阈值、技能池、冷却和转阶段事件。
- 检查阶段是否存在无休止重复技能或危险预算超限。

### Gameplay 调参面板

- 运行时修改武器、后坐、擦弹窗口、冷却和奖励时间倍率。
- 显示玩家状态、当前 ShotPackage、Charge、GrazePhase、反冲资格、连段和伤害来源。
- 只在开发构建启用；保存修改时明确写回哪个配置资产。

## 17.3 测试与复盘工具

- 固定 Seed、固定输入场景和自动重开。
- 伤害、死亡来源、右键尝试次数、防守/动势擦弹成功率、完美率、武器使用率和波次用时统计。
- 局内事件日志，可按 RuntimeId 追踪一颗弹从生成到命中/擦弹/回收。
- 性能预算面板：活跃敌人、弹丸、VFX、音源、GC Alloc 和帧时间。
- Input Debug：当前设备、Action 值、重绑定冲突和焦点丢失。

# 18. 关键运行链路

## 18.1 动势擦弹

```text
玩家按下右键
  -> GrazeRuntime 开启 Active Window
  -> Projectile 进入 Graze Sensor
  -> GrazeRuntime 登记候选
  -> Projectile 未命中 Hurtbox
  -> Projectile 离开 Graze Sensor
  -> GrazeRuntime 校验窗口重叠、反冲状态与去重
  -> IsRecoilMoving 为 true，结算动势擦弹
  -> ChargeRuntime 增加充能
  -> TimeDilationService 提交自动慢动作请求
  -> 发布 MomentumGrazeSucceededFact
  -> Presentation 播放视觉、音频与相机反馈
```

如果 `IsRecoilMoving` 为 false，则只发布 `DefensiveGrazeSucceededFact`，不增加充能、连段或慢动作。

## 18.2 完美动势擦弹

```text
Projectile 命中 Hurtbox
  -> HitResolver 查询右键 Perfect Window
  -> Perfect Window 拦截伤害
  -> Projectile 被销毁或偏转
  -> GrazeRuntime 检查 IsRecoilMoving
  -> 结算 Perfect Momentum Graze
  -> Charge 获得更高收益
  -> TimeDilationService 提交更强的自动慢动作请求
  -> 发布 PerfectMomentumGrazeFact
```

## 18.3 强化射击

```text
WeaponRuntime 确认可发射
  -> ChargeRuntime 为 ShotPackage 生成强化快照
  -> WeaponExecution 应用 EmpowerProfile
  -> 成功生成弹丸并施加后坐
  -> ChargeRuntime 消耗对应等级
  -> 弹丸按快照独立运行，不再读取玩家当前 Buff
```

# 19. MVP 范围与制作顺序

## 19.1 验证原型

只做一个灰盒 Gameplay 战场、一个低压测试波次、散弹枪、射手敌人和调试弹幕，验证五件事：

1. 纯后坐力移动是否在 30 秒内能被理解。
2. 玩家能否预测一次射击后的落点。
3. 玩家是否明白右键是擦弹动作，而不是直接开启慢动作。
4. 防守擦弹、动势擦弹和完美动势擦弹是否能被清楚区分。
5. 动势擦弹的强化是否值得玩家主动规划反冲路线。

这五项未通过前，不做复杂随机池和大量敌人。

## 19.2 可玩闭环

- 三把武器。
- 三种普通敌人。
- 一个完成空间与出生点校验的 Gameplay 战场。
- 一套 5 至 8 波的有序 RunDefinition，包含歼灭与关键目标。
- 8 至 12 个局内奖励。
- 一个两至三阶段 Boss。
- 主菜单、设置、胜败、结算、重开。

# 20. 平衡与验收指标

## 20.1 核心指标

- 新玩家首次理解“开枪会移动我”的时间。
- 新玩家首次主动利用后坐躲开攻击的时间。
- 右键尝试频率、空按率、防守擦弹率、动势擦弹率、完美率和误判投诉。
- 玩家为了动势擦弹而改变射击方向的频率。
- 强化弹命中高价值目标的比例。
- 每把武器的持有率、波次完成率和死亡率。
- 奖励子弹时间触发率、平均持续时间，以及它是否真的促成下一次有效操作。

## 20.2 体验验收

- 玩家死亡后能说出自己为什么死。
- 不看 HUD 也能分辨普通反冲、右键绿色窗口、防守擦弹、动势擦弹、完美动势擦弹和真实受伤。
- 三把武器仅凭后坐节奏就能辨认。
- 关闭震屏和闪光后仍可完整读懂玩法。
- Gameplay 战场中不存在不射击就永远无法脱出的软锁，也不存在必须承伤才能通过的布局。
- Boss 的最优策略仍包含反冲和擦弹，而不是绕圈输出。

# 21. 当前必须锁定的设计决定

本文建议直接采用以下默认答案进入原型：

1. 不使用 WASD，移动完全来自开火后坐力。
2. 右键不再主动开启子弹时间，而是开启短暂的绿色擦弹窗口。
3. 不按右键，敌弹经过外圈不算擦弹；普通近失在离开外圈后才结算。
4. 右键擦弹成功但没有反冲位移时，只提供防守收益。
5. 反冲位移中的动势擦弹才给予充能、连段和自动子弹时间；完美时机给予更高奖励。
6. 充能属于玩家，由下一次成功的 ShotPackage 消耗。
7. 单局使用一个 Gameplay 战场，按 RunDefinition 顺序推进独立 WaveDefinition；进入世界时按 Seed 解析完整 WavePlan。
8. AI 用行为树做选择、能力状态机做执行，二者通过 Intent/Request 接到通用角色模块。
9. Boss 复用敌人框架，只增加阶段、技能预算和破绽机制。
10. 先验证一个战场和低压波次里的“射击、后坐、擦弹、强化”闭环，再扩波次和内容。

# 22. 最终玩法流程

玩家带着一把初始枪进入 Gameplay 战场。初始倒计时结束后，第一波敌人从合法出生点出现，并用前摇告诉玩家弹幕将从哪里来。玩家把鼠标指向敌人，开枪造成伤害，同时被推向反方向。这个后退不是射击附带的麻烦，而是下一秒的位置选择。

当后坐轨迹接近敌弹时，玩家按下右键，角色进入极短的绿色擦弹窗口。若敌弹从外圈安全掠过，系统在它离开时结算动势擦弹；若玩家在最精确的时机用内层接住敌弹，则无伤完成完美动势擦弹。只有这种与反冲位移重叠的成功擦弹才会让画面短暂减速，并为下一枪充能。慢动作里，玩家重新瞄准。下一枪变大、变重，开始穿透敌人；满级时甚至能穿过轻型掩体。开枪之后，玩家又被推往新的位置，循环重新开始。

完成波次后，敌人掉落和可选的波次完成奖励直接留在战场。玩家保持控制，可以在间隔内拾取、换枪或恢复；计时结束后下一波自动开始。选散弹枪，意味着用大幅跳跃穿过战场；选冲锋枪，意味着用连续开火细修路线；选轨道枪，意味着愿意在蓄力期承担风险，换来一次强位移和贯穿。逐渐升高的波次压力与战场构筑改变同一条核心循环，而不是绕开它。

最终波次不强制出现 Boss；它可以是歼灭波、关键目标波或包含 Boss 的高压组合。无论具体配置是什么，它都用更复杂的弹幕与空间压力追问同一件事：你能不能把一颗原本要杀死你的子弹，变成击穿敌人防线的下一枪。完成最终波次目标后，本局胜利。

这就是整套游戏的闭环。
